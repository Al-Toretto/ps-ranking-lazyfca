PROJECT CONTEXT FOR AI ASSISTANTS
=================================

Purpose of this file
--------------------
This file is a detailed handoff for other AI threads that will help with
reference search, related work, formalization, paper writing, and result
interpretation. The project is a PhD research paper draft in machine learning,
artificial intelligence, Formal Concept Analysis, and pattern structures.

High-level research topic
-------------------------
The PhD topic is:

Pattern Structures for Interpretable Machine Learning.

Pattern structures are a generalization of Formal Concept Analysis (FCA). FCA
starts from binary object-attribute data and builds formal concepts: maximal
groups of objects with maximal common descriptions. These concepts form a
concept lattice ordered by generality/specificity. Pattern structures extend FCA
to complex descriptions such as intervals for numerical data, sets,
sequences, graphs, and other structured objects. This makes it possible to use
FCA-style mathematical objects for interpretable machine learning on real data.

The central strengths of FCA and pattern structures are:

1. Interpretability: hypotheses/descriptions are mathematically defined.
2. Conceptual structure: concepts are ordered by generalization and can form
   lattices.
3. Local explanations: a hypothesis can be inspected as a pattern description,
   such as intervals over numerical attributes and selected categorical
   attributes.

The scalability problem
-----------------------
Building full concept lattices or pattern concept lattices can be expensive.
For classification, LazyFCA avoids constructing the full lattice. Instead, it
classifies each query object locally.

In binary classification, the rough LazyFCA procedure is:

1. Given a query object q.
2. Intersect q with every positive training object.
3. Each intersection produces a positive local hypothesis/pattern.
4. Test whether this pattern describes positive objects and avoids negative
   objects.
5. Repeat with negative training objects to produce negative hypotheses.
6. Aggregate the surviving hypotheses to predict the class.

In the current multi-class implementation, the same idea is generalized:

- for each class c, supporters are training objects of class c;
- opposers are all training objects from other classes;
- hypotheses generated from supporters of c vote for class c.

The problem with naive LazyFCA aggregation
-----------------------------------------
LazyFCA still generates many local classifiers/hypotheses per query. Even if
each hypothesis is interpretable, the final explanation can become too large.
Also, using all hypotheses equally can hurt predictive performance because some
hypotheses are weak, redundant, too broad, class-biased, or harmful.

This motivates a ranking-and-pruning approach:

Can we rank local LazyFCA hypotheses by importance, keep only a small top-k
subset, and preserve or improve classification quality while improving
interpretability?

Current paper idea
------------------
The paper studies global pooled top-k ranking of LazyFCA hypotheses.

For each query:

1. Generate hypotheses for all classes.
2. Put all class-specific hypotheses into one common pool.
3. Rank the entire pool by a metric.
4. Keep only the top k hypotheses globally, regardless of class.
5. Predict by counting retained hypotheses per class.
6. If class counts tie, break ties by summed ranking score, then by training
   class prior, then by lower encoded label.

This is different from separately keeping top-k positive and top-k negative
hypotheses. The global pool is important because it lets the ranking function
discard harmful hypotheses regardless of their class. For example, a query may
retain 3 hypotheses of one class and 0 of another if the ranking says those are
the most important.

What the paper should NOT claim
-------------------------------
The paper should not claim to build a state-of-the-art black-box classifier.
It should not claim to beat all strong ML baselines. The realistic target is a
Q3-level journal paper about interpretability, compact local explanations, and
improving LazyFCA aggregation by ranking.

The core claim should be closer to:

LazyFCA generates many interpretable local hypotheses, but naive aggregation
over all hypotheses can be noisy and harmful. A global ranking over all
class-specific hypotheses can select a compact subset that often preserves or
improves predictive quality while reducing explanation size.

The experiment runner is config-driven and incremental. It writes result chunks
per dataset, seed, method, and metric. If a chunk already exists, rerunning the
same experiment skips it. This is important because the full experiments can
take a long time.

The runner streams one test query at a time. It does NOT cache full LazyFCA
explanations because full explanations can require huge RAM/disk. Each full
explanation contains all generated classifiers, and each classifier carries
coverage masks over supporters and opposers. On larger datasets this can exceed
100 GB. Streaming keeps memory bounded by one query's generated hypotheses.

Current command examples:

Run one dataset:

python3 paper_experiments/run_paper_experiments.py --run-name trial_rice --datasets rice --seeds 0

Run full configured experiment:

python3 paper_experiments/run_paper_experiments.py --run-name full_run

Rerunning is incremental. Completed chunks are skipped.

Metrics evaluated
-----------------
The config currently enables all registered LazyFCA metrics. Important metric
families:

Basic contingency:

- tp
- fp
- tn
- fn

Purity and support:

- precision = tp / (tp + fp)
- support = tp / number of supporters
- supporter_opposer_ratio
- error_rate
- lift
- WRAcc
- balanced_precision_proxy
- Youden's J
- Matthews correlation

Information/statistical metrics:

- information_gain
- gini_gain
- chi_squared
- g_test

Log-odds-style metrics:

- log_odds_ratio = (2 tp + 1) / (2 fp + 1)
- log_odds_ratio_log_tp = log_odds_ratio * log(1 + tp)

Geometric/query-locality metrics:

- interval_tightness
- description_volume
- simplicity_prior
- query_binary_similarity
- query_numeric_similarity
- query_similarity

Hybrid metrics:

- query_weighted_precision = precision * query_similarity
- query_weighted_precision_log_tp
- query_weighted_precision_sqrt_tp
- query_weighted_log_odds_ratio = log_odds_ratio * query_similarity
- query_weighted_log_odds_ratio_log_tp
- query_weighted_wracc

Stability-like metrics:

- stability
- robustness
- delta_stability

Important caveat about tp=1
---------------------------
Every generated hypothesis is created from the query and one same-class source
training object. Therefore the source object is covered by construction, so
tp >= 1. A hypothesis with tp=1 covers only its generating source object among
same-class training examples. It is not fake, but it is singleton/source-query
support, not evidence that the pattern generalizes to multiple same-class
objects.

This matters for interpretation:

- tp=1 hypotheses can be useful local, nearest-neighbor-like explanations.
- They should not be described as multi-object generalized rules.
- Support-aware metrics may overreward the tautological source support unless
  handled carefully.

Earlier exploratory observations
--------------------------------
These are provisional observations from old experiments. They should guide
discussion but must be confirmed with the new systematic runner.

Rice:

- precision can suffer from stable tie artifacts at k=1 because many pure
  classifiers tie.
- log_odds_ratio can work well because it breaks ties among pure classifiers by
  tp.
- query_weighted_precision and interval/query-similarity metrics looked strong
  at compact k.

Sonar:

- many or all generated classifiers had tp=1 and fp=0.
- contingency/purity metrics became constant and could not rank meaningfully.
- geometric locality metrics such as interval_tightness/query_similarity were
  strong.

Spambase:

- query_weighted_precision looked strong at small k.
- direct support multipliers could fail because broad negative-class rules had
  much larger tp and dominated positive local rules.

General working hypothesis:

- Locality-aware purity metrics are promising.
- Support should be used carefully, often as a tie-breaker rather than a raw
  multiplier.
- Global pooled ranking is more interesting than class-separated top-k because
  it can discard harmful hypotheses from any class.

Current known runtime issue
---------------------------
The runner streams one query at a time, so RAM is safe, but some datasets are
slow. Page blocks is computationally heavy. The current runner writes chunks
only after a whole dataset/seed finishes. If the computer shuts down during a
long dataset/seed, that seed restarts from the beginning, but previous
completed chunks remain safe.

Potential future engineering improvement:

- Add mid-seed checkpoints every N test queries.
- Store compact prediction accumulators, not full explanations.
- Resume a long dataset/seed from the last completed query.

Suggested paper positioning
---------------------------
The paper should be positioned as:

"An interpretable LazyFCA hypothesis-ranking and pruning study for compact
local classification with pattern structures."

It should not be positioned as:

"A new state-of-the-art classifier that beats all black-box baselines."

Possible title variants:

- Compact Local Classification with Ranked Pattern-Structure Hypotheses
- Ranking LazyFCA Hypotheses for Compact Interpretable Classification
- Accuracy-Compactness Tradeoffs in Lazy Pattern-Structure Classification
- Global Top-k Hypothesis Selection for LazyFCA

Potential paper contributions:

1. Formalize global top-k selection over all class-specific LazyFCA hypotheses.
2. Compare many hypothesis-ranking metrics systematically.
3. Show that vanilla all-hypotheses aggregation can be harmful.
4. Demonstrate compact local explanations using small k.
5. Analyze singleton source-query hypotheses and their interpretation.

Things to be careful about
--------------------------
Do not overclaim:

- If full LazyFCA has bad F1, describe it as noisy aggregation, not as a
  baseline to approximate.
- If a compact metric beats vanilla LazyFCA, the reason may be removal of
  harmful hypotheses, not approximation of the full classifier.
- If a metric works well on one dataset, test whether it generalizes.
- If tp=1 dominates a dataset, explain this as local source-query behavior.
- If runtime is high, distinguish explanation-size reduction from generation
  cost reduction. The current method reduces aggregation/explanation size after
  generation; it does not yet avoid generating all hypotheses.
